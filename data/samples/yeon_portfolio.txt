## 🤖 Project 1. ReNe (Next Recruit): 메타버스 연동 AI 채용 플랫폼
**LangGraph 기반의 Stateful Multi-Agent 면접관 시스템**
*2025.11 ~ 2026.01 (진행 중 / 팀 프로젝트)*

### 1. 프로젝트 개요
텍스트 중심 채용의 한계를 극복하기 위해 UE5 메타버스 환경과 연동되는 AI 면접 시스템입니다. 단순 문답이 아닌, 이전 대화 맥락을 기억하고 꼬리 질문을 던지는 **Stateful AI 면접관**을 구현하여 정량적 평가와 피드백을 제공합니다.

### 2. 사용 기술 (Tech Stack)
- **Language**: Python
- **Framework**: FastAPI, LangChain, LangGraph
- **Database**: MySQL, SQLite, ChromaDB (Vector DB)
- **Tools**: Unreal Engine 5 (Client), Git

### 3. 주요 기능 및 구현 내용

#### A. LangGraph 기반 Multi-Agent 워크플로우
- **구조**: 면접관(Interviewer) → 평가자(Evaluator) → 분석가(Analyst)로 이어지는 순환형 그래프(Cyclic Graph) 설계.
- **기능**: 면접관 에이전트가 질문을 던지면 사용자의 답변을 평가자가 분석하고, 부족할 경우 다시 면접관에게 꼬리 질문 생성을 요청하는 **Human-in-the-loop** 구조 구현.

#### B. Context-Aware RAG 및 정량 평가
- **RAG**: 채용 공고(JD)와 지원자 이력서를 ChromaDB에 임베딩하여, 해당 직무와 지원자 이력에 딱 맞는 맞춤형 질문 생성.
- **평가 알고리즘**: 대화 내용을 분석하여 NCS 기준에 따른 인재 유형을 판별하고 모범 답안(Better Answer)을 제시하는 로직 개발.

### 4. 트러블 슈팅 (Trouble Shooting)
- **이슈 (State Persistence)**: HTTP 통신의 Stateless 특성으로 인해 턴이 지날 때마다 면접 맥락이 초기화되는 문제 발생.
- **해결**: `AsyncSqliteSaver` 체크포인트 시스템을 도입하여 대화 상태(State)를 DB에 영구 저장, 세션이 끊겨도 이전 맥락을 이어가는 연속성 확보.
- **이슈 (비동기 충돌)**: `aiosqlite` 라이브러리 속성 충돌로 인한 런타임 에러.
- **해결**: Monkey Patching 기법을 적용하여 라이브러리 간 호환성 문제를 해결하고 서버 안정성 확보.
- **이슈 (그래프 라우팅)**: 상태 업데이트 후 인터뷰 흐름이 끊기는 현상.
- **해결**: `ainvoke` 실행 시 신규 메시지 이벤트를 직접 주입(Injection)하는 방식으로 자연스러운 대화 흐름 구현.

## 🛠 Project 2. WanteDash: 부트캠프 운영 자동화 시스템
**AI 에이전트 오케스트레이션 및 RAG 기반 자동 응대 서비스**
*2025.09 ~ 2025.10 (팀 프로젝트 / 3명)*

### 1. 프로젝트 개요
부트캠프 운영진의 반복적인 업무(질의응답, 과제 체크, 알림 발송)를 자동화하기 위해 개발되었습니다. 사용자의 의도를 파악해 적절한 전문 에이전트에게 업무를 배분하는 **지능형 관리 시스템**입니다.

### 2. 사용 기술 (Tech Stack)
- **Framework**: LangChain, LangGraph, FastAPI
- **Database**: PostgreSQL (pgvector), SQLite
- **External API**: Google Sheets API, Discord API

### 3. 주요 기능 및 구현 내용

#### A. Multi-Agent Orchestration
- **Router 설계**: 사용자 입력을 분석하여 RAG(질문 답변), Alarm(공지 발송), Submit(과제 제출) 에이전트 중 적합한 경로로 자동 라우팅.
- **Semantic RAG**: 부트캠프 규정집을 pgvector에 벡터화하여 저장, 자연어 질의에 대해 높은 정확도의 규정 기반 답변 제공.

#### B. 운영 업무 자동화 파이프라인
- **과제 관리**: Google Sheets API와 연동하여 수강생의 과제 제출 현황을 실시간 파싱.
- **알림 봇**: 미제출자를 식별하여 Discord API를 통해 마크다운(Markdown) 형식의 독려 알림을 자동 발송.

### 4. 트러블 슈팅 (Trouble Shooting)
- **이슈 (데이터 정합성)**: Google Sheets 내의 비정형 날짜 표기(예: '9/1', '2025-09-01')로 인해 검색 누락 발생.
- **해결**: Pandas의 날짜 객체(datetime) 기반 비교 로직으로 변환하여 표기법에 상관없이 검색 정확도 100% 달성.
- **이슈 (에이전트 동기화)**: 세션 복원 시 어떤 에이전트와 대화 중이었는지 정보가 소실됨.
- **해결**: 세션 객체 내에 에이전트 메타데이터를 포함시키고, 로드 시 자동으로 해당 에이전트를 선택(Select Agent)하는 로직을 설계하여 UX 안정성 확보.
- **이슈 (통신 규격)**: 다중 에이전트 환경에서 JSON/FormData 처리 방식 차이로 인한 422 Error 빈발.
- **해결**: FastAPI Pydantic 모델을 재설계하고 프론트엔드 fetch 옵션을 동적으로 구성하여 API 통신 신뢰도 구축.

## 🛒 Project 3. n분의1: 지역 기반 공동구매·나눔 플랫폼
**대용량 트래픽 확장을 고려한 도메인 설계 및 위치 기반 서비스 구현**
*2024.XX ~ 2024.XX (팀 프로젝트 / 10명)*

### 1. 프로젝트 개요
"같이 사요"와 "함께 나눠요" 기능을 통해 이웃 간의 공동구매와 나눔을 중개하는 플랫폼입니다. 지역 기반 매칭 로직과 거래 상태 관리에 중점을 둔 백엔드 서버를 구축했습니다.

### 2. 사용 기술 (Tech Stack)
- **Backend**: Java, Spring Boot, JPA, QueryDSL
- **Database**: MySQL, AWS S3
- **Infra**: AWS EC2

### 3. 주요 기능 및 구현 내용

#### A. 도메인 주도 설계 및 API 개발
- **상품 도메인 분리**: 공동구매(Purchase)와 나눔(Sharing)의 비즈니스 로직 차이를 반영하여 도메인을 설계하고, 카테고리/태그/지역 필터링이 가능한 조회 API 구현.
- **거래 상태 관리**: 거래 상태(모집중, 거래완료 등)에 따라 노출 여부를 제어하고, 거래 확정 시 회원의 '누적 절약 금액'이 갱신되도록 엔티티 간 책임 분리 설계.

#### B. 위치 기반 서비스(LBS) 로직
- **GeoCoding 연동**: Kakao GeoCoding API를 활용하여 거래 장소의 위도·경도를 자동 추출.
- **지역 필터링**: 회원의 대표 지역(동/구 단위)을 기준으로 상품 검색 범위를 제한하여 불필요한 데이터 조회를 방지하는 쿼리 최적화.

#### C. 이미지 처리 및 스토리지 관리
- AWS S3를 연동하여 다중 이미지 업로드 기능을 구현하고, 상품 유형별 디렉토리 분리 및 유효성 검증 로직을 통해 스토리지 효율성 증대.

## 🚜 Project 4. Farmon: 도농 상생 인력 중개 플랫폼
**조건 기반 매칭 알고리즘 및 견적 시스템 구현**
*2024.01 ~ 2024.02 (팀 프로젝트 / 10명)*

### 1. 프로젝트 개요
초보 농부와 전문 농부의 니즈를 연결하는 인력 매칭 플랫폼입니다. 기존의 게시판 형태를 벗어나 조건에 맞는 상대를 추천하고 견적을 주고받는 프로세스를 시스템화했습니다.

### 2. 사용 기술 (Tech Stack)
- **Backend**: Java, Spring Boot, MySQL
- **Tool**: Git Flow, Jira

### 3. 주요 성과
- **매칭 알고리즘**: 희망 지역, 작물, 경력 등의 조건을 복합적으로 고려하여 최적의 상대를 추천하는 쿼리 로직 개발.
- **견적 시스템**: 견적 요청 → 승인 → 진행 → 완료로 이어지는 상태(Status) 기반의 워크플로우를 RESTful API로 설계.
- **협업**: 10명 규모의 팀에서 Git Flow 전략을 도입하여 브랜치 전략을 수립하고, AWS EC2 배포 환경을 구축하여 CI/CD의 기초 마련.

## 📊 Project 5. 제주도 개인 맞춤형 관광지 추천 시스템
**Cold Start 문제 해결을 위한 콘텐츠 기반 필터링 모델링**
*202X.XX ~ 202X.XX (팀 프로젝트 / 2명)*

### 1. 프로젝트 개요
사용자 리뷰 데이터가 부족한 서비스 초기 단계(Cold Start)를 가정하여, 관광지의 메타 데이터를 활용해 개인 취향에 맞는 여행지를 추천하는 ML 모델을 개발했습니다.

### 2. 사용 기술 (Tech Stack)
- **Stack**: Python, Scikit-learn, Pandas

### 3. 주요 내용
- **데이터 전처리**: 제주 관광지 메타 데이터의 결측치를 보정하고 텍스트 데이터를 정제.
- **모델링**: 관광지의 속성(태그, 카테고리)을 벡터화한 뒤 **코사인 유사도(Cosine Similarity)** 기반의 콘텐츠 기반 필터링(CBF) 알고리즘을 구현하여 Top 5 추천 리스트 생성.
- **회고**: 텍스트 외에 이미지 등을 활용한 멀티모달 모델링의 필요성과 MLOps 도입의 중요성을 체감하는 계기가 됨.
